# Body Mesh Provider

![Four body meshes rendered with Body Mesh Intrinsic Camera](Documentation/Images/body-mesh-provider-four-body-camera.png)

A macOS [Fabric](https://github.com/Fabric-Project/Fabric) plug-in for posing
mapped USDZ characters with CoMotion. It also reads body-mesh assets generated by
[CMResearchKit](https://github.com/jvcleave/FabricBodyMeshProvider/releases/download/1.0/CMResearchKit-Example-1.0-arm64.dmg)
and exposes them as time-varying Satin geometry.

The plug-in provides **Body Mesh Character Asset** for mapped USDZ references,
**Character Inspector** for optional visibility and material controls,
**CoMotion Data** for shared archive playback, and **Body Mesh View** for posing
and placement with **Body Mesh View Camera**. **Body Mesh Character** also
supports a self-contained character, and **Body Mesh Provider** supplies
geometry for Fabric meshes.

## Asset paths

Leave **Store Absolute Path** off in a model, motion archive, or asset folder
picker to save a relative path for assets inside the scene directory. Assets
elsewhere use absolute URLs. Turn the option on to keep the selected location
fixed when you move the scene. **Body Mesh Character** has a separate option
for its model and motion archive.

## Body Mesh Provider

**Body Mesh Provider** is a time-based geometry node that reads v2 or v3
CoMotion archives. Select the folder containing `frames.bin` in the node's
Settings panel. Choosing a folder loads it on the next graph frame, even if it
is already selected. The panel
reports compatibility, native frame rate, frame count, duration, and any
loading error.

The node reconstructs the requested archive frame as Satin geometry that can be
connected to Fabric's existing Mesh node and material system. It follows graph
time by default. Connect the **Time** input to use an external clock, or adjust
**Playback Rate** to speed up, slow down, or reverse graph-time playback.

Use **Confidence** to reject uncertain detections and **Maximum Bodies** to
limit how many of the highest-confidence people are included. Selected bodies
are combined into one geometry; the archive does not provide stable person
identities across frames.

Compact Creator v3 archives pose the bundled Default Human and publish its
deformed positions, normals, and UVs to the Geometry port.

For full CoMotion v2 archives, Body Mesh Provider uses GPU skinning
automatically. The CPU calculates CoMotion's shape and pose corrections, and
Satin's vertex shaders apply joint transforms
when drawing the mesh. Use a material that supports Satin skinning. A CPU reader
of the geometry sees positions before joint transforms on the GPU path. Frames
with projective joint transforms use CPU reconstruction for the per-vertex
perspective divide.

Along with **Geometry**, the node reports detected and output body counts,
current frame, native frame rate, frame count, duration, frame availability,
and source dimensions. The **Source Size** output can drive Body Mesh Intrinsic
Camera when source-matched framing is desired.

### Port reference

| Port | Direction | Fabric type | Default or requirement | Description |
| --- | --- | --- | --- | --- |
| `Time` | Input | `Float` | Graph time when unconnected | Playback position in seconds. When connected, this value is authoritative and `Playback Rate` is ignored. |
| `Loop` | Input | `Bool` | `true` | Wraps playback to the beginning when it reaches the end of the asset. When disabled, playback holds the first or last frame. |
| `Playback Rate` | Input | `Float` | `1` | Multiplies graph-time playback speed when `Time` is unconnected. Use values below `1` for slower playback, values above `1` for faster playback, or a negative value to play in reverse. |
| `Confidence` | Input | `Float` | `0.2` (range `0.05...1`) | Minimum confidence required for a detected body to be included. |
| `Maximum Bodies` | Input | `Int` | `1` (range `1...8`) | Maximum number of highest-confidence bodies merged into the geometry. |
| `Primitive` | Input | `String` | `Triangle` | Selects `Point`, `Line`, `Line Strip`, `Triangle`, or `Triangle Strip`. |
| `Geometry` | Output | `Geometry` | — | Selected bodies merged into one indexed Satin geometry. Connect this to Fabric's Mesh node. |
| `Detected Bodies` | Output | `Int` | — | Number of bodies stored in the current frame before confidence filtering. |
| `Output Bodies` | Output | `Int` | — | Number of bodies included after confidence filtering and the `Maximum Bodies` limit. |
| `Current Frame` | Output | `Int` | — | Zero-based archive frame represented by the current geometry. |
| `Frame Rate` | Output | `Float` | — | Native frame rate encoded in the selected asset. |
| `Frame Count` | Output | `Int` | — | Total number of frames in the selected asset. |
| `Duration` | Output | `Float` | — | Total asset duration in seconds. |
| `Frame Available` | Output | `Bool` | — | `true` when at least one body passes filtering for the current frame. |
| `Source Size` | Output | `Vector 2` | — | Encoded source width and height. Connect this to `Body Mesh Intrinsic Camera` for source-matched framing. |

## Body Mesh Character

Add **Body Mesh Character** from Fabric's Loader group. It opens with Creator's
neutral rigged USDZ. **Choose Character Model** selects a mapped Creator USDZ
and **Use Default Human** restores the bundled model. **Choose Motion Archive**
accepts a `frames.bin` file, a Creator `.messcapture`, or a folder containing the
archive. Use **Time**, **Loop**, and **Playback Rate** for local archive playback.
The character shows its reference pose when both motion sources are unset.
Each selected detection draws with its own pose and camera translation.

| Motion archive | Body Mesh Character | Body Mesh Provider geometry |
| --- | --- | --- |
| Compact v3 from Creator or MESS | Default Human or a selected mapped USDZ | Posed Default Human |
| Full CoMotion v2 | Default Human or a selected mapped USDZ with the recorded rigid poses | Reconstructed shape and pose from the recording |

CMData from CMCaptureKit validates and indexes compact v3 archives. The plug-in
reads full v2 records locally to retain recorded shape and projective transforms.
Default Human uses the MakeHuman Community's MPFB base mesh and GameEngine rig
assets. [CC0 1.0 Universal](https://creativecommons.org/publicdomain/zero/1.0/)

Imported textures respond to Satin lighting. Character surfaces use the
authored alpha cutoff in both the visible image and the shadow map.

Add a Directional Light and connect **Source Size** to **Body Mesh Intrinsic
Camera** for source-matched framing. The model and archive choices are saved
independently for graph reopen and movie export.

The plug-in build requires Apple silicon, macOS 15.6 or newer, an Xcode
toolchain with Swift 6.2 or newer, and read access to two private dependencies.
[MessUSDZImportKit](https://github.com/jvcleave/MessUSDZImportKIt) · [CMCaptureKit](https://github.com/jvcleave/CMCaptureKit)
Xcode embeds the OpenUSD and TBB frameworks and the USD schema resources in
the plug-in. [USDZ update plan](docs/internal/todos/USDZ_CHARACTER_MODEL_UPDATE_PLAN.md)

## CoMotion Data

Add **CoMotion Data** from Utility. Choose a v2 or v3 `.bin` file, a Creator
`.messcapture`, or a prepared folder containing `frames.bin`. Use **Time**,
**Loop**, and **Playback Rate** to control the archive.

Connect **CoMotion Frame** to the matching inlet on each **Body Mesh Character**.
The shared frame drives playback when connected. Each character applies its own
model, **Confidence**, and **Maximum Bodies**. **Body Mesh View** accepts the
same frame output and applies it to the selected USDZ. Connect **Source Size**
to either body mesh camera for source-framed rendering.

### CoMotion Data port reference

| Port | Direction | Fabric type | Default or requirement | Description |
| --- | --- | --- | --- | --- |
| `Time` | Input | `Float` | Graph time when unconnected | Selects an archive frame by time in seconds. A connection sets the playback time directly. |
| `Loop` | Input | `Bool` | `true` | Wraps playback. Turn it off to hold the first or last frame outside the archive's range. |
| `Playback Rate` | Input | `Float` | `1` | Multiplies graph-time playback when `Time` is unconnected. Negative values play in reverse. |
| `CoMotion Frame` | Output | `Dictionary of Array of Float` | — | Contains the selected frame's detections, pose parameters, and motion metadata. |
| `Source Size` | Output | `Vector 2` | — | Encoded source width and height for camera framing. |

### Body Mesh Character Asset port reference

| Port | Direction | Fabric type | Default or requirement | Description |
| --- | --- | --- | --- | --- |

## Character Inspector

With the graph running, open a character asset's Settings and choose **Add
Character Inspector**. The action connects the asset to an inspector and
inserts it into a single direct **Body Mesh View** connection. For a shared
asset, wire the inspector's **Character** output to the view input you want
to control. You can also add **Character Inspector** from Utility and connect
it manually.

In the inspector's Settings, select targets by name and USD path.

- **Mesh Visibility Inlets** adds a Boolean toggle for each selected mesh.
- **Material Visibility Inlets** adds a Boolean toggle for all surfaces that use
  the selected material.
- **Material Replacement Inlets** adds a Material inlet. Connect a Fabric
  material node to replace the imported material on those surfaces. Disconnect
  it to restore the authored material.

Toggle a visibility inlet on the node or wire it to a Boolean source. To give
it a short label such as **Gun Visible**, right-click the inlet and choose
**Publish**, then right-click it again and choose **Rename…**. Save the scene
to keep the name.

```text
Body Mesh Character Asset ──► Character Inspector ──► Body Mesh View / Character B
                               Gun Visible   ◄── Boolean control
                               Body Material ◄── Physical Material
```

The slot can also take the asset's **Character** output directly. Each slot
can have its own overrides when both refer to the same USDZ.
[Character Inspector update plan](docs/internal/todos/CHARACTER_INSPECTOR_UPDATE_PLAN.md)

### Character Inspector port reference

| Port | Direction | Fabric type | Default or requirement | Description |
| --- | --- | --- | --- | --- |
| `Character` | Input | `Virtual` | Connect a Character output | Accepts a USDZ file reference from an asset or the result of another inspector. |
| `<Mesh> Visible` | Input | `Bool` | `true` (expose in Settings) | Controls every surface on the selected mesh. |
| `<Material> Material Visible` | Input | `Bool` | `true` (expose in Settings) | Controls every surface bound to the selected USD material. A surface draws when both its mesh and material visibility allow it. |
| `<Material> Material` | Input | `Material` | Expose in Settings, then wire a Fabric material | Replaces the material on every surface bound to the selected USD material. An empty inlet uses the incoming character's material choice. |
| `Character` | Output | `Virtual` | — | Sends the USDZ reference and its overrides to Body Mesh View or another inspector. |

## Body Mesh View

Connect the **Character** output from a **Body Mesh Character Asset** or a
**Character Inspector** to **Character A** and optionally to **Character B**.
Connect **CoMotion Frame** from **CoMotion Data**.
The view prepares both connected models when their references change.
**Character Index** selects A at `0` and B at `1` while CoMotion Data continues
playing. The view applies its **Confidence** and **Maximum Bodies** filters to
the current frame. Use **Position**, **Orientation**, and **Scale** to place
the view in the Fabric scene and add a scene light to illuminate it.

Turn on **Draw Bounding Box** to render a wireframe around the active pose's
visible meshes. The box follows the view and appears in preview and export.

**Camera Distance** sets the pivot depth measured from the capture eye.

### Body Mesh View port reference

| Port | Direction | Fabric type | Default or requirement | Description |
| --- | --- | --- | --- | --- |
| `Character A` | Input | `Virtual` | Connect a Character output for index `0` | Accepts a USDZ file reference from an asset or a character with inspector overrides. |
| `Character B` | Input | `Virtual` | Connect a Character output for index `1` | Optional second character slot with the same accepted values as `Character A`. |
| `Character Index` | Input | `Int` | `0` (range `0...1`) | Selects `Character A` at `0` or `Character B` at `1`. |
| `CoMotion Frame` | Input | `Dictionary of Array of Float` | Connect CoMotion Data | Supplies the detections and poses for the selected character. |
| `Camera Distance` | Input | `Float` | `0` (nonnegative) | Sets the distance from the capture eye to the view pivot in scene units. |
| `Draw Bounding Box` | Input | `Bool` | `false` | Draws the posed bounds of the visible character meshes. |
| `Confidence` | Input | `Float` | `0.2` (range `0.05...1`) | Filters detections from the incoming frame by confidence. |
| `Maximum Bodies` | Input | `Int` | `1` (range `1...8`) | Limits the character instances to the highest-confidence detections. |
| `Visible` | Input | `Bool` | `true` | Shows or hides the view in the scene. |
| `Render Order` | Input | `Int` | `0` | Inherited Fabric input, reserved on this node. |
| `Position` | Input | `Vector 3` | `(0, 0, 0)` | Places the view pivot in world units. |
| `Scale` | Input | `Vector 3` | `(1, 1, 1)` | Scales the view along each axis. Each factor must be positive. |
| `Orientation` | Input | `Vector 4` | `(0, 0, 0, 1)` | Orients the view using an `(x, y, z, w)` quaternion. |
| `Camera Transform` | Output | `Transform` | — | World transform of the capture eye. Connect it to Body Mesh View Camera to follow the view. |

## Body Mesh View Camera

Connect **Camera Transform** from **Body Mesh View** and **Source Size** from
**CoMotion Data**. The camera follows the view and retains the source framing.
Other Fabric cameras can see the view in the scene.

### Body Mesh View Camera port reference

| Port | Direction | Fabric type | Default or requirement | Description |
| --- | --- | --- | --- | --- |
| `Camera Transform` | Input | `Transform` | Optional | Sets the camera's world transform from Body Mesh View. An empty inlet uses the camera's local pose. |
| `Source Size` | Input | `Vector 2` | `(1920, 1080)` | Encoded source width and height used to calculate the field of view. |
| `Orientation` | Input | `Vector 4` | `(0, 0, 0, 1)` | Local camera orientation as an `(x, y, z, w)` quaternion. |
| `Scale` | Input | `Vector 3` | `(1, 1, 1)` | Local camera scale along each axis. |
| `Position` | Input | `Vector 3` | `(0, 0, 0)` | Local camera position in world units. |
| `Visible` | Input | `Bool` | `true` | Sets the camera object's visibility flag. Fabric selects the active camera by scene order. |
| `Render Order` | Input | `Int` | `0` | Inherited Fabric input, reserved on this node. |

## Body Mesh Intrinsic Camera

**Body Mesh Intrinsic Camera** is an optional perspective-camera node designed
to reproduce the framing used by the body-mesh generator. Connect the Body Mesh
Provider's **Source Size** output to the camera's **Source Size** input.

The camera derives its field of view from the source dimensions and adjusts it
as the Fabric viewport changes. Its aspect-fit projection preserves the
generated mesh's original horizontal and vertical framing across different
output aspect ratios.

The camera defaults to the origin and looks along Fabric's negative Z axis,
matching the coordinate conversion performed by Body Mesh Provider. Position,
orientation, and scale remain available for creative adjustments.

This is a deterministic reconstruction of the generator's camera model. It
does not recover lens distortion, principal-point offsets, physical focal
length, or the original camera's position and orientation. Ordinary Fabric
cameras remain fully supported when source-matched framing is not required.

### Port reference

| Port | Direction | Fabric type | Default or requirement | Description |
| --- | --- | --- | --- | --- |
| `Source Size` | Input | `Vector 2` | `(1920, 1080)` | Encoded source width and height. Connect the provider's `Source Size` output here. |
| `Orientation` | Input | `Vector 4` | `(0, 0, 0, 1)` | Camera orientation as an `(x, y, z, w)` quaternion. The identity orientation looks along Fabric's negative Z axis. |
| `Scale` | Input | `Vector 3` | `(1, 1, 1)` | Scales the camera view along each axis. |
| `Position` | Input | `Vector 3` | `(0, 0, 0)` | Camera position in world units. Generated body meshes are calibrated with the camera at the origin. |
| `Visible` | Input | `Bool` | `true` | Sets the camera object's visibility flag. Fabric selects the active camera by scene order. |
| `Render Order` | Input | `Int` | `0` | Inherited Fabric input, reserved on this node. |

Body Mesh Intrinsic Camera has no output ports. Fabric discovers camera nodes in
the graph directly and uses its normal active-camera selection behavior.

## Development layout

The default local layout is:

```text
MAC_APPS/
├── Fabric/
└── BodyMeshProvider/
```

The Xcode target builds against an adjacent checkout of the
[Fabric repository](https://github.com/Fabric-Project/Fabric). Override its
location with the `FABRIC_SOURCE_ROOT` build setting when necessary.

## Build and install

Open `BodyMeshProvider/BodyMeshProvider.xcodeproj` and build the
`BodyMeshProvider` scheme, or run:

```sh
xcodebuild \
  -project BodyMeshProvider/BodyMeshProvider.xcodeproj \
  -scheme BodyMeshProvider \
  -configuration Debug \
  -destination 'platform=macOS' \
  build
```

The build prepares the matching Fabric Swift module, builds the plug-in, copies
the constants into its resources, installs it at the path below, and ad-hoc
signs the installed bundle:

```text
~/Library/Application Support/Fabric/Plugins/BodyMeshProvider.fabricplugin
```

Use the same build configuration for Fabric Editor and the plug-in. Restart
Fabric Editor after rebuilding because Fabric discovers plug-ins when its node
registry starts.

## Use in Fabric

### Character Inspector sample

Open [Character Inspector.fabric](FabricScenes/Character%20Inspector.fabric)
and play the graph. In **Published**, set **Character Index** to `0` for the
authored USDZ or `1` for the inspected version. **Gun Visible** controls one
gun mesh and **Body Color** drives the replacement Physical Material on the
inspected branch. The scene opens at `1` with that gun hidden.

Both branches use `human2.usdz` and the same CoMotion playback. Keep the
`Character Switching` asset folder beside the scene when moving it.

### Character Switching sample

The scene alternates `human1.usdz` and `human2.usdz` over one CoMotion archive.
Both character assets, **CoMotion Data**, **Body Mesh View**, and **Body Mesh
View Camera** are visible on the root graph. Use **Frames per Character** to
set the switch interval and **Body Mesh View** to place the active character.
In the Published inspector, set **Camera View** to `0` to follow the view or
`1` to use the fixed **Scene Camera Pose**. Both viewpoints use the
capture lens and share the same running CoMotion stream. Use **Draw Bounding
Box** to show the posed character's bounds. Move the sample folder with both
USDZs and `motiondata.bin`.
[Character Switching.fabric](FabricScenes/Character%20Switching/Character%20Switching.fabric)

### Character sample

Open [Character-sample.fabric](FabricScenes/Character-sample.fabric). It
connects **Source Size** to **Body Mesh Intrinsic Camera** and uses **Default Human**
with the included [24sectest archive](FabricScenes/947B44F8-C4C3-4666-93B5-73BD71CE231A).
The checked-in scene references that archive folder relative to the graph.
Keep the graph beside the archive folder when moving the sample. In the node's
Settings, choose a Creator USDZ to see it follow the same motion or choose
another archive to keep moving the same model with a different capture.

### Geometry provider sample

Open [`FabricScenes/Sample.fabric`](FabricScenes/Sample.fabric) for a basic
working scene. Its **Asset Folder** points to the included
[24sectest folder](FabricScenes/947B44F8-C4C3-4666-93B5-73BD71CE231A) relative
to the scene. Keep the scene and asset folder together when moving the sample.

### Four-body camera sample

Open [`FabricScenes/Camera-sample.fabric`](FabricScenes/Camera-sample.fabric)
with the included 24sectest folder beside it. For the original
four-performer example, expand the release archive and select its
`C00F9E45-6C83-4760-A700-BBF2A37D0380` directory in Body Mesh Provider Settings.
[Four-performer archive](https://github.com/jvcleave/FabricBodyMeshProvider/releases/download/1.0/C00F9E45-6C83-4760-A700-BBF2A37D0380.zip)

**Maximum Bodies** to `4`, allowing all four performers in the sample to be
included when their confidence passes the node's threshold.

### Build a scene manually

To build a scene manually:

1. Add **Body Mesh Provider** from the Geometry node group.
2. Open the node's Settings and choose an output folder created by the generator
   app.
   The panel reports compatibility, native frame rate, frame count, duration,
   and any loading error. Use **Reload** after repairing an asset in place.
3. Connect **Geometry** to Fabric's existing Mesh node, then attach a material
   and render it normally.
4. Use graph time for ordinary playback, or connect **Time** to make an external
   clock authoritative.
5. For source-camera framing, add **Body Mesh Intrinsic Camera** and connect the
   provider's **Source Size** output to its **Source Size** input. The camera
   becomes the graph's active camera using Fabric's usual last-added-camera
   behavior.

The node exposes Loop, Playback Rate, Confidence, and Maximum Bodies controls,
plus body count, frame rate, frame count, duration, frame availability, and
source-size metadata.

## Tests

The core package has no Fabric, Satin, SwiftUI, or CMResearchKit dependency:

```sh
swift test --package-path BodyMeshProviderCore
```

The checked-in example asset is always exercised. Additional local archives
under `SampleData` are exercised when present and remain ignored by Git.
